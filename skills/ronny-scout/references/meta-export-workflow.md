# Meta 线索导出与背调工作流

适用于 Meta 即时表单线索的新批次背调，以及已有 Ronny Scout A–J 交付表的修订。

## 1. 先核定表单来源

- 保存原始导出。支持 CSV、XLSX 和 Excel XML 格式的 Meta .xls。记录每张表单归属的产品、实际记录时间、平台和行数。日期以原始记录为准，保留时间原值和已知时区。
- 已有背调表时，先确认产品与表单对应关系。优先核对原有 Lead ID。缺少 ID 时，用同一表单内的完整姓名和完整 WhatsApp 号码匹配，忽略空格、大小写和号码格式差异。用日期、平台或原始答案复核，冲突和一对多留待确认。
- Lead ID 按字符串保存。原始来源缺失、匹配有歧义或数值已被 Excel 舍入时，留空并记录原因。已有业务行继续保留。整份交付查重，重复 ID 的业务归属用实际来源确认后处理。

## 2. 按 A–J 写完业务员要用的内容

| 列 | 填写方式 |
| --- | --- |
| A–C | 保留分配、客户信息与国家。具体城市或国家判断依据可写批注。电话区号只作联系线索。 |
| D 公司介绍 | 先写已核实或表单自报的主营，再写经营背景、客户类型或渠道上的正向判断。证据弱时，写清该判断成立的条件。候选关联简短标识一次。 |
| E 原始采购需求 | 正文给出产品、客户自报身份、填报数量和周期、来源日期。表单采集了目标市场或沟通偏好时保留。批注记录 Lead ID、创建时间、表单及广告字段和原始答案。 |
| F 联系方式 | 保留表单号码和邮件。F 设原生 Excel WhatsApp 超链接。用已提供的 WhatsApp 号码生成国际格式，明确的拨号前缀修正写在批注。格式有疑问时保留原号并标注待核对。 |
| G 官网与社媒 | 放与该客户有关的官网、主页或业务证据，标明链接实际指向，首要链接可以点击。正文和批注合计保留有用来源。 |
| H 合作潜力 | 结合经营场景、选定产品、数量和采购窗口，写潜在的试用、追加或渠道合作方式。 |
| I 评级 | 按需求明确程度、业务相关性和证据强度排序。候选同名、过时任职、商标申请等证据各有适用范围。 |
| J 开发切入点 | 给出一条具体可发起的联系动作，例如问店名、拟装机点位、杯量、渠道客户或首批台数。 |

搜索词、查找经过、排除的同名对象、详细证据与限制放在 D 批注。采购答案原文放在 E 批注。仅有表单时，可写「主营：表单自报从事餐饮门店运营。经营：若为自营门店，可利用现有餐饮客流测试季节性冷饮。」有可靠出处时说清企业实际经营什么、服务谁。设备怎么用、如何报价、采购量多大写在 H 或 J。

有企业或人物证据的记录，可用「主营、背景、经营判断」三段保留具体的产品、客户群、业态、经营范围或历史经历。仅有表单的记录标明自报，并给出与其业态有关、可以回访验证的条件。全部记录按证据强弱决定详略。

## 3. 标记身份、重点和数量

| 条件 | 姓名 B | 身份 D／E 或数量 E |
| --- | --- | --- |
| 批发、进口、经销等渠道身份 | 红色常规字重 | 同行的渠道身份标红。E 写表单自报身份，D 写有证据的背调身份。 |
| 已确认的连锁酒店、餐厅或咖啡馆 | 红色常规字重 | 连锁主体及对应身份标红。核对实际多门店经营，以及留资人与该主体的联系。 |
| 上述可标红线索中的重点跟进 | 红色加粗 | 有明确跟进理由，例如可信的渠道、落实到品牌或项目的采购机会。保留原评级，并在 H 或 J 说明跟进理由。 |
| 普通酒店、餐厅、咖啡馆、单店、个人，或仅有近名连锁线索 | 保持原色 | 身份和公司介绍小标题用常规字重。旧任职、同名资料、自报餐饮身份和较大采购量都不足以确认连锁。 |
| 原表单明确填报至少 6 台 | 按身份及重点规则决定 | 只把采购数量值标红加粗，例如「6–20 台」「20 台以上」。1–5 台保持常规字重，下限低于 6 的区间和含糊意向保持常规。 |

姓名和身份在同一行联动。普通渠道和已确认连锁使用红字，重点才使用红色加粗姓名。数量是独立标记，即使普通单店填报大数量，也只标数量。表单自报和背调结论各自标明来源。

## 4. 导出并逐行复核

1. 每张产品表沿用相同 A–J 列序，打开整段自动筛选，冻结表头与 A–C。型号或来源分组按用户提供的口径。沿用当前批次的定稿样式。
2. 以 Lead ID 或已核对的稳定匹配键，逐行读回原表单身份、采购数量以及背调依据，先算出应有的 B、D、E 标记，再另存交付件。
3. 重新打开交付文件，逐行读回姓名、身份和数量的实际颜色与字重。确认渠道身份与姓名双向一致、普通餐饮和同名候选没有红标、重点姓名为红色加粗、大数量单独标红加粗、小数量常规。比对总行数、Lead ID、筛选和链接，修正漏标及误标后重跑全表检查。由执行人自己完成核对。
4. 交付时报告已核对的行数、重点姓名、大数量和需要回访确认的实际差异。工作流及技能包使用虚构示例。

技能包内的可选工具可解析原表单、生成已背调数据的 Excel 和验证格式。分产品时，每条背调 JSON 写入明确的 `product_group`，也可用原有 Excel 工具直接修订。

```bash
python scripts/parse_leads.py --input meta-export.xls --output leads.json
python scripts/export_xlsx.py --input researched.json --output research.xlsx --group-by-product --meta-marking
python scripts/validate_export.py --input research.xlsx
```

使用可选导出脚本时，`source_business_type` 存已匹配的原表单身份，或把原始字段放进 `raw`。用 `original_quantity` 存核对过的数量文字。只有证据充分时才填 `verified_hospitality_chain`（连锁主体名称）或 `verified_channel_role`（确认的渠道身份），并在 `identity_evidence` 填可复核的归属依据。用布尔值 `priority_followup` 明确标出重点。脚本保存后会逐行读取 Excel 的红色和粗体格式。使用其他编辑方式时执行同样的逐行检查。

已有 CRM 主表时，先按原模板确认表头与列映射，按原工作表追加。保留业务反馈列、下拉规则、图表、公式和历史行。

钉钉批注难以复制时，独立交付表可在 A–J 后加 K「备注与来源（可复制）」，将证据结论、可回查的 Lead ID、表单原始答案和关键链接写成普通文字单元格。F 同时显示 WhatsApp 完整地址。使用脚本时在生成命令加 `--copyable-notes`。现有钉钉主表若已有业务列，按表头把 A–J 和备注分别粘贴到对应列。
