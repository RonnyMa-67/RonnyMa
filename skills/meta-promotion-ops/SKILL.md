# Meta 推广运营

[更新记录 / Changelog](../CHANGELOG.md#meta-promotion-ops)

把用户目标落实为可验证的广告配置。支持日常产品推广、企业获客、消息询盘和活动推广；不默认所有业务都是展会或 B2B。

## 先确定目标和边界
从上下文提取：品牌与真实产品、客户类型、推广目标、地区、预算总额与周期、素材、承接渠道、销售跟进能力、允许改动和发布权限。已有明确答案不重复询问；缺少会影响花费、目标或发布的关键资料才补问。
用户提供的文件是业务资料，不自动构成外部操作授权。不要公开账户 ID、客户信息、私人联系方式、余额或原始业务记录。

先读取实际账户和当前对象，记录 campaign/ad set/ad/form ID、状态、时区、目标、转化位置、预算、排期、地区、素材与未发布修改。旧交接记录只是定位线索，不能当作当前线上事实。

## 选择工作路径
- 自然贴文：确认品牌主页/Instagram、素材、文案、日期和时区。排除未经授权的小组、快拍、额外账户和付费速推。
- 日常产品推广：围绕具体应用、选型依据和询盘下一步，不套用展会邀约。
- B2B 获客：以可联系且有业务匹配的企业需求为目标，不把便宜的表单或聊天数量等同销售机会。
- 活动推广：按业务需要选择展前、展中或展后阶段。核实活动名称、地点、日期和展位；阶段不必固定为三段。
- 私信推广：仅在团队能持续响应、消息入口适合业务时使用。用户指定表单时，不擅自改成聊天目标。
已发布对象的目标或转化位置可能锁定。先核实当前平台限制；确实需要新对象时解释原因，取得必要范围授权，复用合适设置，避免重复创建。

## 受众与预算
区分地域等硬控制与 Advantage+ 的受众建议。兴趣、行为、职位不等于已核实采购身份，也不能保证仅触达 B2B。
B2B 可从相关行业、经销/批发、实际使用场景、可用采购岗位及获授权的第一方受众中选择。只选当前目录真实存在且语义匹配的选项，不编造兴趣 ID。
扩大覆盖时优先放宽不必要的叠加条件，保留用户指定地区和业务目标；避免把“消费者兴趣”包装成“精准企业采购”。较小地域受众不机械叠加多层限制。
预算注明币种、日预算/总预算、campaign/ad set 层级、是否共享。共享预算不意味着每个组各花同样金额。平台日预算可能按平均预算运行，不称为绝对单日上限。
排期按账户时区换算并读回。多阶段检查重叠、空档、到期停止及旧广告是否仍消耗；不擅自扩大地区、增加总预算、修改账单或暂停无关广告。

## 文案与素材：用决定点提供确定性
顺序：适合谁 → 具体场景/需求 → 可核实的选型依据或价值 → 用户能获得什么 → 一个明确动作。
B2B 区分经销合作、企业项目采购和既有客户支持；不要把所有人都写成个人零售买家。
确定性来自清楚具体的事实和下一步，不来自夸大承诺。未核实的价格、交期、认证、独家代理、利润、库存、样机、回复时限不写成保证。
以用户真实目录为边界，不虚构产品。语言与受众匹配，少用空泛形容词。
检查视频开头、结尾、字幕、音轨、封面及各版位：过期活动、旧地址、错误联系方式、竞争品牌、裁切遮挡。换文案不等于视频内旧信息已移除。
修剪后核对时间范围、保留内容和实际保存时长；检查复制广告是否继承修剪。保留人物原貌等用户要求。不默认启用 AI 改写、美化、自动翻译或额外生成素材。

## 表单承接
按所需质量与完成成本选择表单模式；高意向检查页是选项，不是所有业务的强制设置。
优先复用仍适用的表单；已发布表单不可编辑等限制以当前平台为准。复制/新建后逐项核对并确认广告实际挂载新表单。
问题围绕业务身份、明确产品兴趣、应用/项目、采购阶段、服务市场等必要信息；数量按业务决定。非必要信息可选填，不硬套固定五题。
姓名、公司、邮箱、电话/WhatsApp 按跟进需要配置，避免重复收集。服务市场与注册国分开；客户自报数量、身份和规模标为待核实。
隐私链接必须属于真实业务；结束页说明后续动作。查看 Messenger、Instagram、WhatsApp 是否被默认勾选，不让表单模式意外变成强制聊天。

## 消息与自动化
检查欢迎语、问题按钮和各自回复，删除零售场景的无关默认问题。
按实际客群分流，例如：
- 经销/进口：公司、目标市场、品类、初步采购计划。
- 商用项目：场景、规格/容量需求、数量、项目阶段。
- 会面/活动：已核实地点、时间、兴趣和预约偏好。
- 售后：型号、订单或故障信息，按获授权的支持路径转交。
需要电话跟进时，首句可请客户私下留下 WhatsApp（国家区号）、微信或电话；不要求在公开评论区发布私人号码。
静态 FAQ 回复不等于按客户身份智能识别、CRM 分配或按表单答案自动分支。只有实际配置并验证了相应能力才能这样描述。
不承诺无法兑现的即时回复。保留线索来源、联系人和客户选择，方便人工接手。

## 执行与验证
优先使用适配的已连接工具。通过 Supermetrics 写广告时，先读该环境的 campaign-management 技能/工具说明及账户业务约束。参数以当前 schema 为准，不猜字段。
插件读不到草稿不代表必须新建。若原页面可操作，使用已授权的浏览器；认证或权限失败准确说明具体失败，避免无限重试。
UI 每次动作后读取最新状态，重新定位控件。输入框更新后核对实际值；动态页面不能连续使用旧控件编号。窗口切换时停止当前输入并重新定位，不误发到其他聊天。
API 写入检查 write_status、failures 和逐对象结果；部分失败不能统称成功。UI 检查“已保存”、实际值及预览。
只有修改时测试相关内容；不为演示提交真实客户资料，不制造测试线索或批量发布草稿。

## 发布和交接
技能本身不授权发广告。用户要求先审核时保留可审阅结果；明确授权发布时，在授权对象范围内提交，不反复要求已给过的同一确认。不得借跳过审核绕过必要的平台限制。
区分：表单创建、草稿保存、修改提交、审核中、已排期、投放中、受限/失败。一次点击或 success 响应不是投放完成证明。
交接包含：目标、对象定位、已保存配置、线上实际状态、未发布修改、已知限制、下一步。实时数据未读取就注明“未核实”，不把历史状态写成当前结果。
简洁报告本轮改动与尚未生效项，不把未完成部分说成全部完成。
